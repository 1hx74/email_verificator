## 1. Отправка кода подтверждения

**`POST /api/mail/send`**

### Request:

```json
{
    "email": "string"
}
```

### Response `200 OK`:

```json
{
    "code": 200,
    "state": "OK"
}
```

После успешного выполнения запроса сервис:

1. генерирует случайный шестизначный код;
2. вычисляет `SHA-256` от сгенерированного кода;
3. сохраняет хэш кода в БД вместе с email и временем окончания действия;
4. отправляет исходный код на указанный email.

Сам код в открытом виде в БД **не хранится**.

Для одного email одновременно может существовать **только один активный код**. При повторной отправке новый код заменяет предыдущий активный код.

### Срок действия кода

Код действителен в течение заданного времени, по умолчанию **5 минут**.

После истечения срока действия код считается недействительным.

### Errors:

#### `400 Bad Request` — некорректный email

```json
{
    "code": 400,
    "state": "Invalid email"
}
```

#### `429 Too Many Requests` — превышено количество запросов

```json
{
    "code": 429,
    "state": "Too Many Requests"
}
```

Ограничение применяется для предотвращения большого количества запросов на отправку кодов.

#### `503 Service Unavailable` — ошибка сервиса отправки почты

```json
{
    "code": 503,
    "state": "Mail service unavailable"
}
```

Возвращается, если сервис не смог отправить письмо.

## 2. Проверка кода подтверждения

**`POST /api/mail/verify`**

### Request:

```json
{
    "email": "string",
    "verification_code": "XXXXXX"
}
```

`verification_code` должен содержать **ровно 6 цифр**.

При проверке сервис вычисляет:

```text
SHA-256(verification_code)
```

и сравнивает полученный хэш с хэшем, сохранённым в БД.

### Response `200 OK`:

Успешная проверка:

```json
{
    "code": 200,
    "state": "OK",
    "verification": true
}
```

Неверный код:

```json
{
    "code": 200,
    "state": "OK",
    "verification": false
}
```

При успешной проверке код становится недействительным и не может быть использован повторно.

### Errors:

#### `400 Bad Request` — некорректный email или код

```json
{
    "code": 400,
    "state": "Invalid request"
}
```

#### `404 Not Found` — активный код для email не найден

```json
{
    "code": 404,
    "state": "Verification code not found"
}
```

Возвращается, если в БД отсутствует активная запись для указанного email.

#### `410 Gone` — код истёк

```json
{
    "code": 410,
    "state": "Verification code expired"
}
```

Возвращается, если код существует, но срок его действия истёк.

#### `429 Too Many Requests` — превышено количество попыток

```json
{
    "code": 429,
    "state": "Too many verification attempts"
}
```

Возвращается при превышении допустимого количества попыток проверки одного кода.

## 3. Ограничения

### Код подтверждения

* состоит ровно из 6 цифр;
* генерируется криптографически стойким генератором псевдослучайных чисел (через python модуль secrets);
* имеет ограниченный срок действия;
* хранится в БД только в виде SHA-256 хэша;
* после успешной проверки становится недействительным;
* для одного email одновременно существует только один активный код.

### Ограничение попыток

Количество неправильных попыток проверки одного кода ограничено. После N проверок (по умолчанию 5) - код инвалидируется

### Ограничение отправки

Количество запросов на отправку кода для одного email ограничено во времени.

По умолчанию: **не более 1 нового кода в 60 секунд**
